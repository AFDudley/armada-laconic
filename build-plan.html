Build plan — status & backlog

What exists, what needs work, and what is genuinely net-new — per tier, with pinned code and a per-component confidence mark. The Architecture page is the structure; this is the status.

Version scope (epics)

The work splits into three clearly different scopes. v1 is what Armada needs now; the ex_net matcher and everything it implies is a separate v2 feature; hiding amounts from the venue is v3.

v1 — Armada supportprivate, mobile-first USDC rails + a posted-price venue + clearing + yieldE1 private sync (T1/T2) · E2 clearing over Nitro · E3 posted-price venue · E4 mobile client (T6) · E5 private transport · E6 CCTP private rail (T5) · E7 Design A boundary (T0) · E8 thin identity · base yield (wstETH note / LP-buffered Aave)
v2 — ex_net / matcherprice discovery + market-makingFBA / curve / CLOB-RFQ matcher + LP / market-maker vault + native LP yield (T4) · the whole fair-ordering stack: commit-reveal + post-seal beacon + sequencing certs + DA + epoch set-agreement + watchtower (T3)
v3 — Design Bhide trade amounts/terms from the venue itselfZK matching + shielded ForceMove (deferred / research)
Why the split de-risks v1: a posted-price, take-it-or-leave-it venue has nothing to front-run, so v1 needs neither commit-reveal ordering nor the epoch set-agreement — the two highest-risk, research-grade items. They move to v2 with the matcher. v1 collapses to integration of shipped components + a small posted-price contract + the Design A boundary adapter — no new consensus/ordering protocol, no ZK-circuit research. The v1 money side is detailed in Yield & clearing.

T0 · Ethereum anchor

Built: Railgun pool (Armada's, immutable); full Nitro adjudicator / ForceMove / MultiAssetHolder, live on Ethereum[5]. Net-new:

  • Venue/party registry + bond — the federation's on-chain entry point; where membership and slashing settle.
  • Sequencing-cert + fraud-proof verifier — an L1 contract that verifies the party's aggregate Schnorr signature[13], so a bad ordering/censored commit is slashable against the bond.
  • Nitro↔Railgun boundary adapter — note-funded, note-settled channels (Design A privacy boundary).

T1 · Ingestion

Built: plugeth[16] + statediff[17] + ipld-eth-*[18]; the generic watcher-ts framework[2]. Net-new / integration: a Railgun-pool + Nitro-adjudicator watcher config, and the metered private-note-stream serving on top of it. This tier is what protects the anonymity set at read-time.

T2 · Watcher-party substrate

Built: Nitro metering (vouchers[8] / virtual channels[9]); p2p relay (mobymask[3] / ts-nitro[4]); the Schnorr DSS library[13]. Net-new: federation membership/bonding coordination; the DKG ceremony + resharing and wiring chain-signatures into the signing paths; STUN/TURN is commodity ops.

T3 · Ordering

The highest-design-risk, mostly net-new tier. Net-new: commit-reveal mempool + post-seal randomness beacon; epoch set-agreement (leader-proposes + threshold-attest + receipt-backed censorship fraud proofs — deliberately not BFT); DA publish of the revealed epoch; a watchtower. Threshold-signed inclusion receipts reuse the DSS signing that already exists[13]; the sequencing protocol around it is new.

T4 · Execution platform (ex_net)

The one validated tier — read in depth this cycle. Reusable: the 2019–2020 matcher PoC[24] (frequent-batch-auction, curve-order, filler-filtered CLOB/RFQ, multi-pair rings — see Execution platform); go-nitro channels/virtual[9], swap protocol[6], ForceMove[5]. Net-new: productionize the matcher; the LP / market-maker vault; receipt-or-slash + commit-reveal settlement wiring; multi-asset outcomes.

T5 · Adapters

Built: CCTP (Armada's). Net-new (thin, on T4): the Swaps adapter (exposes "swap shielded A→B" over the matcher) and the yield adapter (ex_net native LP yield + private route into Aave v4). Audit note: ex_net as a shared substrate under multiple adapters has its own audit boundary — a deliberate deviation from Armada's per-adapter audit discipline.

T6 · Client / apps

Reality check: the wallet is bare-bones and MobyMask[3] / the swap demos are demo fragments, not user-facing products — a real starting point, not a finished front-end. Reusable: laconic-wallet[21] / -web[22]; in-browser Nitro node[4]. Net-new: grow the wallet into the Armada-branded front-end + wire the Armada SDK; wallet updates (return pubkey on cosmos_signAmino, Nitro + commit-reveal integration, Railgun boundary UX).

Open decision — mobile p2p transport. A working browser libp2p stack already exists (MobyMask: @cerc-io/peer + in-browser Nitro + Noise + webrtc-star/circuit-relay + gossipsub), but the RN wallet runs no libp2p today (WalletConnect only). Three paths:

Verdict: "Waku is an easier port" is denied as a near-term generalization — reuse the existing browser stack (A). Waku (B) wins only for always-on / background messaging, where a WebView is undermined (iOS WKWebView JS suspension when backgrounded, battery, unreliable persistent WS/WebRTC). Caveats: @waku/sdk (Waku-in-JS) repackages the same RN libp2p-noise problem — only the native go-waku binding is a true RN win; and Waku replaces messaging, not Nitro's channel transport (still bridge Nitro over Waku content topics).

Net-new backlog (roughly sequenced)

  1. Contracts (T0): venue registry+bond → sequencing-cert + fraud-proof verifier → Nitro↔Railgun boundary adapter.
  2. Ordering (T3): commit-reveal + beacon → epoch set-agreement (the real research-adjacent lift) → DA publish → watchtower.
  3. Platform (T4): productionize matcher → LP / market-maker vault → receipt-or-slash + force-close/commit-reveal wiring → multi-asset outcomes.
  4. Threshold (T2): DKG ceremony + resharing + integrate chain-signatures into signing paths.
  5. Adapters (T5): swaps-on-matcher; yield (native LP + private route to Aave v4).
  6. Client (T6): grow the bare-bones wallet into the Armada-branded front-end + wire the Armada SDK; wallet updates; decide mobile p2p transport (reuse browser stack in WebView vs go-waku native).
  7. Ingestion (T1): Railgun/adjudicator watcher config + metered private note stream.
  8. Identity (×-cut): selective-disclosure proofs; Matchmaker integration (if in scope).

One-line shape: T0–T2 is mostly built/integration; the genuine new build is T3 ordering + T4 platform + the T0 contracts. Deferred (Design B): ZK matching + shielded ForceMove to hide trade amounts from the venue itself; native BTC settlement beyond an HTLC leg.
