Armada × Laconic

Laconic delivers two things for Armada's shielded pool: the mobile-first private support services that surround it, and more yield on top. Armada builds the crypto core; Laconic provides the substrate around it and the yield.

for: Armada team non-custodial pool untouched Ethereum L1-anchored status: scope + code-fit map

Armada is pluggable asset-privacy infrastructure for USDC: a shielded pool (Railgun ZK circuits, immutable), governance-added adapters (CCTP, Aave v4 yield, swaps), and an apps/SDK tier, funded by integrator revenue-share. This site details how Laconic slots into that model — as the private, mobile-first substrate the pool depends on, and as new yield sources on top. Companion docs: the thesis (why Laconic is the substrate), the ex_net whitepaper (the 2017 design ancestor), and the glossary (terms & word-collisions across Laconic / Nitro / Railgun).

What Laconic delivers

1 · Mobile-first support services

The private, mobile-first substrate that runs Armada on phones and browsers with almost no fixed infrastructure.

  • Private sync — proof-carrying note streams that protect the anonymity set at read-time (Armada's core fragility: it dies at read-time over normal RPC).
  • Metering — pay-per-request Nitro vouchers.
  • Front-end — the Laconic wallet is a bare-bones React Native app, and MobyMask / swap are demo fragments — the right starting point, which we build up into the Armada-branded app.
  • Client + relay — keys + Cosmos/EIP-155 signing + in-browser Nitro node + libp2p relay.
  • Deploy / ops — bonded service-provider federations run it; monetized via Armada's integrator revenue-share.

2 · More yield

Yield plus a simple private exchange, cleared non-custodially over Nitro — a posted price in v1, market-making later.

  • ETH yield — a shielded wstETH note: intrinsic, non-rebasing staking yield; no Aave or LP needed.
  • USDC yield — an LP-buffered, batched Aave rail (non-custodial), plus posted-price spread + clearing fees.
  • Engine now: posted price + clearing (Yield & clearing); the ex_net matcher is the v2 price-discovery upgrade.

How it plugs into Armada

ex_net is not a sibling adapter — the venue is a private execution/settlement layer beneath the Adapters tier: in v1 a posted-price venue + clearing over Nitro, upgradable to the v2 ex_net matcher for price discovery. Armada's Swaps and yield adapters are applications on it; the shielded pool stays immutable and untouched; everything is non-custodial.

Honest scope notes

  • Shared substrate ⇒ its own audit boundary. Putting ex_net under multiple adapters makes it a shared dependency — a larger surface than one independently-deployed adapter, and it needs its own audit. Worth stating plainly against Armada's "each adapter independently deployed & audited" discipline.
  • Pool stays immutable. ex_net operates at the adapter/execution tier; nothing here alters Armada's core contracts or takes custody.
  • Depth is uneven. Only the execution platform (ex_net → matcher) has been validated in depth so far; the rest is design-level / net-new. The Build plan marks per-component confidence.
