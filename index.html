Armada

Armada is a shielded pool for private USDC, built by one engineering team working from the ship-armada repos. The pool, its circuits, the settlement rail on Nitro state channels, and the web client are built. The proof path, a mobile client, and any exchange venue remain a plan.

non-custodial Ethereum L1-anchored pool built, 50 bps shield fee

Armada is asset-privacy infrastructure for USDC: a shielded pool, spec-compatible with the Railgun design and independently authored; governance-added adapters for cross-chain transfer (CCTP, built) and yield (Aave-v4, built); and a web client (`armada-interface`), wired to the pool through `armada-sdk`. See the glossary for terms across the pool, Nitro, and the proof path.

Settlement over Nitro — built

ArmadaNitroAdjudicator carries the deposit/payout boundary inside itself: a shielded note funds a Nitro channel (depositFromNote), the channel runs off-chain, and a SHIELD-type allocation shields the outcome back into fresh notes on payout. Because the movement happens off-chain, there is no per-transaction event on the pool to link against.

  • Clears the exchange. Not built. No posted-price venue or matcher exists yet; swaps and yield that clear through a venue remain a plan.
  • Moves value across chains. CCTP is built: PrivacyPool/PrivacyPoolClient/CCTPHookRouter shield and unshield across chains, USDC-only. The hub-fronted cross-chain-swap design over Nitro channels (see shielded-nitro-bridge-design.html) is not built; HubCustodian exists and signs with FROST, but no client drives a channel through it yet.
  • Brings existing balances in. Not built. The wallet move from Railgun (unshield there, shield here) is designed (ADR-0006) but has no code in armada-interface yet.

The on-chain anchor overview covers what is built; the cross-chain-swap construction is still a design document.

What is built

The on-chain anchor

The pool, the circuits, the adjudicator, and governance.

  • Pool. `PrivacyPool`, routed by delegatecall to four modules, no proxy, a 50 bps deployed shield fee.
  • Circuits. `Transact(N,M)`, 19 shapes. The production Phase-2 ceremony has not run.
  • Adjudicator. A patched `go-nitro`, with the deposit/payout boundary merged in.
  • Governance. `ArmadaGovernor`, `ArmadaTreasuryGov`, `ArmadaToken`, `ArmadaCrowdfund`, `ArmadaWindDown`, `ArmadaRedemption`, and the revenue contracts.

Yield

Two mechanisms, both built.

  • ETH. A shielded wstETH note carries intrinsic staking yield; no new contract is needed.
  • USDC. `ArmadaYieldAdapter`/`ArmadaYieldVault`, a direct recipe through the pool's own `adaptContract` binding, not Railgun's RelayAdapt/Cookbook, which this codebase does not use.

What is still a plan

  • The proof path. The nimbus verified proxy is the intended trust boundary (see engineering/09-architecture-decisions.html#adr-0009); it runs nowhere in Armada's stack today. A client reads chain state over RPC or an unverified cache.
  • A mobile client. armada-client has no application code. armada-interface, the live web app, is the only shipped client.
  • A settlement-client channel lifecycle and a watchtower. The adjudicator side is built and tested; no client drives it.
  • An exchange venue. No posted-price contract, quote/settle app, or matcher exists.
