Mobile end-to-end privacy

Trace a mobile user's private swap through every privacy layer — device → network → transport → read → order → submit → settle → identity — with the code that implements each, and an honest scope of what it takes to integrate on a phone.

Mobile integration difficulty: Low config / wire-up of existing prod code · Med integration + gaps, components exist · High net-new protocol / circuit / native-module / research

Source-verified across three research passes (network/transport, sync/submit/order, settlement/identity). Code links use GitHub where a mirror exists, else the Laconic Gitea git.vdb.to; mtm-vpn-client is private (SSH-only). This complements the Architecture tier stack and the Build plan status.

The privacy flow (a mobile private swap)

  DEVICE            keys never leave phone (secure enclave)                    [L3]
    │  on-device mnemonic → HD keys (react-native-keychain)
    ▼
  NETWORK / IP      Nym mixnet underlay hides IP + traffic metadata           [L1]
    │  5-hop mixnet  (or 2-hop AmneziaWG for latency)   · zk-nym creds
    ▼
  TRANSPORT         two modes, both libp2p, both tunneled through Nym         [L1]
    │  ├─ Waku pub/sub  → broadcaster / discovery / async  (recipient-unlinkable)
    │  └─ direct libp2p-noise stream → Nitro hot loop  (tens-of-ms; enc+auth only)
    ▼
  READ  (sync)      watcher serves proof-carrying, same-bytes note stream     [L2] ★
    │  phone scans/decrypts notes LOCALLY → no RPC fingerprints you
    ▼
  ORDER            commit-reveal + post-seal beacon (venue can't front-run)   [L2]
    │  commit=H(order‖salt) → seal → beacon → reveal → match
    ▼
  SUBMIT (write)    broadcaster/keeper submits tx → on-chain origin ≠ your EOA [L2]
    │  Railgun Broadcaster over Waku · Laconic keeper · gasless
    ▼
  SETTLE (value)    Railgun shielded pool (notes/nullifiers) + Nitro channel  [L3]
    │  non-custodial · force-close escape hatch · Design A boundary
    ▼
  IDENTITY         optional, selectively-disclosed proof (else identity-blind) [L3]
       onboarding eth-sig + kyc_id · ex_net proofs · FHE matchmaker

★ = the single property Armada's anonymity set depends on (read-time interest-privacy). If reads leak, everything downstream is moot.

Nym is a packet tunnel; Waku/libp2p are app overlays. Once the Nym TUN is up, every socket the app opens (go-waku and direct libp2p) transits it automatically — no per-library work for the async path. But routing the direct-noise hot loop through the 5-hop mixnet re-adds the latency the direct path exists to avoid, so the hot path realistically uses Nym 2-hop Fast mode (or bypass). WebRTC-star (UDP/ICE) may not cleanly traverse a WireGuard TUN — the least-proven combination. [INFERENCE]

What still leaks (honest residuals)

  • Design A: the venue sees trade amounts/terms + an ephemeral per-channel identity. It does not learn who you are, fund origin, history, or that two channels are you. Hiding amounts/terms from the venue = Design B (ZK matching + shielded ForceMove), out of scope for v1.
  • Anonymity set is finite: Railgun crowd size + Waku topic-anonymity size bound the guarantees; subject to amount/timing correlation — mitigate with denominations/batching + a fresh per-channel identity.
  • CGNAT is not privacy: gives no guarantee vs the live counterparty; IP privacy must come from Nym.
  • Waku exposes the requesting node's IP to lightpush/filter/store peers unless tunneled through Nym.

Integration difficulty — scoping the assembly

The privacy primitives mostly exist and are individually production-grade. The cost is almost entirely mobile-runtime integration (React Native runs none of the p2p/prover stacks natively today) plus ~5 net-new pieces. Ranked crux items:

Reusable today (Low / wire-up)

  • On-device key custody — ships in the wallet (only new signing paths are additive).
  • Nitro adjudicator / ForceMove — live on Ethereum; mobile side via ts-nitro in a WebView.
  • Railgun shielded pool — live (Armada's, immutable) — we consume, not build.
  • NymVPN client — shipped Android/iOS (in-house fork); wire-up, not build; embedded-wallet-from-mnemonic precedent exists.
  • Keeper relay + broadcaster — Railgun broadcaster is prod; keeper submit is a trivial RPC (PoC lineage).
  • Onboarding proof — a Cosmos msg the wallet nearly signs already (add eth-sig + pubkey return).
Bottom line. No new cryptography is required for v1 (Design A) — the hard work is (a) making a phone run two libp2p transports + a ZK prover under a mixnet VPN, and (b) building four net-new protocol/contract pieces (boundary adapter, ordering, pool watcher, and gluing them). The load-bearing, do-first item is #5 read-time private sync — if reads leak, the entire pool anonymity set collapses and the rest is moot.
