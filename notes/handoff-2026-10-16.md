### 4.5 Procedure for a pebble

1. File with `exophial intake`: observations only in every field. Check each body with
   `find_interpretive_markers` (must print `()`), then `--dry-run`. Then record `exophial pebble estimate <id>
   --points N`: the context-fit gate refuses a pebble without that record, and `--estimate` at filing does not count.
2. After the spec link appears, a comment may point to existing code (facts only). A comment before the spec link
   can become an acceptance clause.
3. Dispatch only admissible ids. A parked id makes `exophial dispatch` exit non-zero, and the ephemeral reducer then
   stops and kills the worker it just started.
4. After each landing, the git index of `.pebbles/events.jsonl` lags behind `HEAD` (`exo-cba`). If the bus file
   equals `HEAD` (`git diff HEAD --quiet -- .pebbles/events.jsonl`), run `git reset -q -- .pebbles/events.jsonl`.
5. A parked pebble: first classify it with the skill `exophial-pebble-triage`
   (`exophial/.claude/skills/exophial-pebble-triage/SKILL.md`) and do the action its table names (`:177-185`).
   - Worker exited without a handoff and left commits: keep the worktree and the branch, `exophial pebble unpark
     <id>`, dispatch. The reconcile resumes the kept work (`SKILL.md:112-124`).
   - Gate failure: keep the branch (`git branch -m worker/<id> wip/<id>-attemptN`), remove the worktree, add a
     facts-only comment, unpark, dispatch. The comment cites the failure message and the contract's file:line, never
     a sample output (a sample became a hardcoded constant in `arn-5db`).
6. An operator-known change that touches no `scripts/`, `tests/` or `contracts/specs/`: commit on a branch in a
   `.scratch/` worktree, then `TMPDIR=$PWD/.scratch exophial apply <branch> --title ... --reason ...`.
