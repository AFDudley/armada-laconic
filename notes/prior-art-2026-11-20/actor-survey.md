# Actor models and communicating-state-machine formalisms: prior art for the planned Lean 4 DSL

Scope: Hewitt's and Agha's actor model, Erlang/OTP engineering forms, formalized actors (Rebeca, a Rocq
actor-language mechanization), actor-based and typestate smart-contract languages, I/O automata, TLA+
composition, session types and typestate, and verified distributed-system refinement frameworks (IronFleet,
Verdi, Ivy, P, Disel), plus a check for Lean 4 work on actors, process calculi, or I/O automata. Cardano and
Cardano-ecosystem tools are out of scope; a separate review covers them.

Required reading done in full before this synthesis: `armada-laconic/docs/process.md` (Practice 1: read every
source in full, and the anti-pattern "rebuilding a tool's own mechanism") and
`armada-laconic/labbook/2026-11-20-temper-and-the-dsl.md` §3-4 (the planned DSL). `ArmadaLean/Machine.lean:23`
(`structure Machine`, generic `init`/`step`/`Reachable`/`invariant`) and `ArmadaLean/Nitro/Reachable.lean:510`
(`structure Network`, one shared `chain` field, operator ruling 2026-10-29 rejecting `Machine.interleave`) were
also read directly.

This file synthesizes four subagent reports, each reporting primary sources read in full or to the cited
section: `local://actor-survey-classic.md`, `local://contract-lang-survey.md`,
`local://actor-survey-automata-protocol.md`, `local://verified-systems-prior-art.md`. Those files hold longer
per-row citations; this file compresses them to one table. A claim not read in a primary source by the
contributing subagent carries `[INFERENCE]`.

## The seven questions

1. State and invariant representation (type-carried or proved per transition).
2. Composition and shared-state representation.
3. Honest/adversarial/environment move separation; game or liveness reasoning.
4. Proof obligations generated from a declaration.
5. Refinement to running code; one model, several targets.
6. Tool, maintenance state, license.
7. (answered in the ranked list below, not per cell, to keep the table readable)

## What each formalism already provides for the planned DSL (one line each)

1. **Hewitt 1973** — nothing mechanizable; conceptual ancestor of "per-declaration obligation, inherited by composition" only.
2. **Agha et al. 1997** — a composition operator for actor configurations; no `embeds`, no generated obligations.
3. **`gen_statem`/`gen_server`** — an engineering precedent for environment events (`state_timeout`) and for `embeds`-as-API-boundary; no formal machinery.
4. **Rebeca/Timed Rebeca** — the strongest actor-calculus precedent for environment events (time-progress transition); checks by model checking, not theorem generation.
5. **Core Erlang in Rocq** — a modular layered-semantics pattern and a multi-constructor signal type (adjacent to owner tags); no `embeds`, no per-declaration obligations.
6. **I/O automata** — input-enabled design and per-component fairness classes; shared state is modeled as its own automaton via synchronization, not as `embeds`.
7. **TLA+ composition** — the cleanest formal precedent for `embeds` (`μ_k` shared-state rule) and for a three-way ownership split (`E ⊢→ M`); no code generation.
8. **Typestate (Strom & Yemini)** — the precedent for the DSL's own `Pre`/outcome-indexed-`Effect` call shape; no composition or embedding story.
9. **Session types** — a duality operator guaranteeing complementary two-party protocols; no n-party generalization exists yet for Nitro's shared chain.
10. **Scilla** — a `Pre`/`Effect`-shaped transition and an induction-over-trace invariant proof shape matching `Machine.invariant`; nothing for `embeds` or owner tags.
11. **Obsidian** — the strongest precedent for the DSL's second (client-code) target; nothing for `embeds`, owner tags, or generated obligations.
12. **Flint** — caller-capability gating, adjacent to but not the same as owner-tagged moves; one target only.
13. **Move / Move Prover** — the strongest precedent for generated proof obligations (`spec` to SMT) and for scoping an obligation to the owning module (`acquires`, invariant clusters); nothing for owner tags or multi-target.
14. **Pact** — a second strong generated-obligation precedent (`@model` to SMT-LIB2); nothing for composition, owner tags, or multi-target. No longer maintained.
15. **Bamboo** — confirms Obsidian's state-machine structuring is recognized elsewhere; no new mechanism.
16. **IronFleet** — the layered-refinement shape Armada's `docs/process.md` already adopted; nothing for `embeds` or multi-target.
17. **Verdi** — a reusable pattern for adding environment events as a transformer rather than baked-in cases; nothing for `embeds` or owner tags.
18. **Ivy** — an interactive invariant-discovery technique, usable when Lean automation stalls; its flat relational state is the shape the 2026-10-29 ruling already rejected.
19. **P language** — the strongest precedent for owner-tagged moves (ghost/real machine split with erasure); nothing for `embeds` or per-call obligation generation.
20. **Disel** — the strongest precedent for `embeds` (send-hooks) and literature confirmation that shared state needs more than free composition; nothing for owner tags or liveness.
21. **Lean 4 actors/automata** — nothing exists to adopt.

**No single formalism already provides the planned DSL.** Nothing in this survey combines all four of: declaration-generated proof obligations, `embeds`-shaped nested shared state, owner-tagged (honest/adversary/environment) moves, and a multi-target code generator. Each piece has a separate, citable ancestor (Move Prover for obligation generation, Disel/TLA+ for `embeds`, P language for owner tags, Obsidian for multi-target), but no tool or paper assembles them. Armada's planned `machine`/`contract`/`implements … via` triple is a novel assembly of existing, individually-precedented ideas, not a duplicate of an existing tool. This matches the finding against `embeds` specifically: actor models (rows 1-5) structurally forbid nested state by design (Agha et al. 1997, §1: "the internal state of a component must only be accessible through operations provided by the interface"), so `embeds` has no actor-calculus precedent at all; its nearest ancestors are state-machine refinement formalisms (TLA+, Disel), not actor calculi.

## Ranked design ideas worth copying, for `embeds`, owner-tagged moves, and environment events

### For `embeds`

1. **Disel's send-hooks.** A precondition-strengthening predicate attached to a specific transition tag of the embedding machine, restricting a client transition unless a condition on the embedded (core) machine's state holds — the client reads and constrains the core only through the core's own transitions firing the hook. Source: Sergey, Wilcox, Tatlock, POPL 2018, §1.2 and §3.1 ("hook", Fig. 6). Worth a direct design comparison against the current `Network.chain`-field approach (`ArmadaLean/Nitro/Reachable.lean:510`) before `embeds` is fixed.
2. **TLA+'s Shared-State Composition Rule (`μ_k`).** The embedding machine's spec states explicitly which changes to the shared variable are "not caused by me"; this is the closest already-formalized device to "`Network.chain` changes only through `Network`'s own calls that defer to the adjudicator's own `apply`." Source: Lamport, *Specifying Systems*, ch. 10, §10.4.1, pp. 144-147.
3. **Move Prover's invariant "cluster" scoping and `acquires` annotation.** Scope the one-preservation-obligation-per-call rule to the smallest set of declarations that can invalidate it: a call on the outer machine that does not touch the embedded field should not re-prove anything about the embedded machine's own `apply`. Source: Dill, Grieskamp, Park, Qadeer, Xu, Zhong, arXiv:2110.08362, §3.1 ("acquires") and §3.2 ("Modular Verification").
4. **Erlang's `gen_server`/`gen_statem` API-boundary discipline.** An informal but load-bearing real-world precedent: a resource's state changes only inside its own callback module, never touched directly by callers. Source: `erlang.org/doc/apps/stdlib/gen_server.html`.

### For owner-tagged moves (honest/adversary/environment)

1. **P language's ghost-machine/real-machine split with type-checked erasure.** Represent an environment (or adversary) participant as a tagged machine in the same language as honest participants, with a compiler-checked erasure proof that the tagged machine never appears in the generated target. The clearest existing mechanism for a honest/environment distinction, already proved sound. Source: Desai, Gupta, Jackson, Qadeer, Rajamani, Zufferey, PLDI 2013, §3.3.
2. **TLA+'s open-system `E ⊢→ M` rely-guarantee operator.** A working, already-formalized environment/system split, generalizable to a three-way honest/adversary/environment tag by chaining more than one conjunct. Source: Lamport, *Specifying Systems*, §10.7, pp. 156-158.
3. **Erlang/OTP `gen_statem`'s event-type tag (`call`/`cast`/`info` vs. `timeout`/`internal`).** Tags each event by origin, orthogonally from its effect; `state_timeout` fires with no caller at all, a working precedent for "no transaction calls this move." Source: `erlang.org/doc/apps/stdlib/gen_statem.html`, "Event types" and "Time-Outs".
4. **Core Erlang's one-inductive-type-of-signal-kinds pattern.** `Signal ::= msg | exit | link | unlink` as alternative constructors of one relation is a directly reusable Lean pattern: a `Move` inductive with `honest`/`adversary`/`environment` constructors, each with its own payload type, consumed by one `step`. Source: Bereczky, Horpácsi, Thompson, arXiv:2311.10482, Def. 3.4.
5. **I/O automata's input-enabled restriction.** Every automaton must accept every input in every state; it can restrict what it promises in response but can never structurally block an input. The right default for an adversary-owned call: dispatch to `none` on failed precondition, never exclude the call structurally. Source: Lynch & Tuttle, 1989, "Overview of the Model", p.2.

### For environment events

1. **Timed Rebeca's time-progress transition.** A transition kind formally distinct from *event* and τ, firing with no actor or message driving it — the strongest actor-calculus precedent for "time advances; no transaction calls them." Source: Sirjani & Khamespanah, arXiv:2309.07302, §3, Fig. 1(a).
2. **Erlang/OTP `gen_statem`'s `state_timeout`/`generic_timeout`.** The clearest engineering-layer precedent: these actions fire from the runtime, not from any caller. Source: `erlang.org/doc/apps/stdlib/gen_statem.html`, "State time-out" section.
3. **TLA+'s open-system operator**, reused here as the formal environment-event split (see item 2 above under owner-tagged moves).
4. **Verdi's verified system transformers.** Implement "time advances" or "network unreliable" as a transformer applied to a `machine` declaration, extending its `Call` type and transporting existing preservation/can-happen proofs, rather than requiring every `machine` author to hand-add environment cases. Source: Wilcox et al., PLDI 2015, §2.4.
5. **Scilla's syntactically distinct deep-read (`x <- && g`).** Marks a chain-level read at the point of use, distinct from a contract's own field access (`x <- & f`) — a model for how an `Effect` should mark a read of environment-level state that no call controls. Source: Sergey, Kumar, Hobor, arXiv:1801.00687, §2.3.
